Feature Flag

Dynamic feature flag only — no static Cargo feature

The address registry instructions are always compiled into MIR and the kernel. No #[cfg] gating. Activation is controlled at runtime by a dynamic feature flag in durable storage, following the existing kernel pattern for enable_dal, enable_fa_bridge, enable_tezos_runtime.

/evm/feature_flags/enable_address_indexing

Pattern from kernel/src/storage.rs:

  1. Storage path: RefPath::assert_from(b"/evm/feature_flags/enable_address_indexing")
  2. Existence = enabled: host.store_has(&PATH)?.is_some() (no data, just path existence)
  3. Read at boot: added to ExperimentalFeatures struct in kernel/src/chains.rs
  4. Boot parameter: --enable-address-indexing passed to kernel installer
  5. Runtime toggle: store_write to enable, store_delete to disable

Where the check happens

At typechecking time, in the MIR typechecker. typecheck_script receives an allow_address_indexing: bool parameter. When false, INDEX_ADDRESS and GET_ADDRESS_INDEX are rejected with a typechecking error — origination fails, exactly as before the feature was implemented (no regression).

The kernel reads ExperimentalFeatures::is_address_indexing_enabled() once at boot and passes the flag to every typecheck_script call (origination + execution). When the flag is turned on, contracts using these instructions can be originated and executed.

No check is needed in mir_ctx.rs (index_address/get_address_index) because the typechecker blocks upstream.

Architectural Decisions

D1: Methods on CtxTrait, behind feature flag

LazyStorage is separate because BigMap methods consume it as parameter (map.mem(&key, *ctx.lazy_storage())). index_address / get_address_index are called directly by the interpreter, like voting_power() or origination_counter(). Two methods don't justify a separate trait + boxing indirection.

All behind #[cfg(feature = "address-registry")] — when disabled, CtxTrait is unchanged, no stubs needed.

D2: Return Result

In the kernel, host.store_write() can fail. The in-memory Ctx never fails — but the trait must accommodate both. New variant InterpretError::AddressRegistryError(#[from] ...) follows the LazyStorageError pattern.

D3: BigUint everywhere

Michelson nat = BigUint in MIR. Same as level(), voting_power(). No u64 intermediate.

D4: get_address_index(&self)

Verified: Runtime::store_read() takes &self. Interpreter holds &mut ctx — &self methods are callable via reborrow.

D5: Empty registry in Default

Zero address at index 0 is a protocol invariant, enforced by address_registry_storage.ml at context init. MIR's Ctx::default() starts with an empty HashMap. Tests call ctx.index_address(&zero_addr) explicitly when needed. Kernel enforces it at genesis.

Persistence & Invariants

Idempotency

HashMap::entry(addr).or_insert_with(|| ...): if key exists, no mutation occurs. Same address always returns same index. Kernel: store_read first — if found, return without writing.

Unique, monotonically increasing indices

Counter increments only in or_insert_with. Each address inserted at most once. N distinct addresses → indices 0..N-1.

Entrypoint stripped

Interpreter uses &addr.hash only. KT1xxx%default and KT1xxx%do → same index. Matches OCaml address.destination.

Rollback preserves consistency

Kernel: registry lives under /evm/world_state/indexes/address_registry/. SafeStorage snapshots /evm/world_state — both counter and entries are restored atomically on batch failure. No orphan indices.

Internal op failure: parent's writes persist (correct L1 behavior — each transaction is atomic unto itself).

Path safety — no collision across address variants

AddressHash::to_bytes() prepends a type tag: 0x00 (implicit), 0x01 (KT1), 0x03 (sr1). A KT1 and tz1 with identical raw hash produce different byte sequences → different hex → different storage paths. Verified in address_hash.rs:185-199.

hex::encode produces only [0-9a-f]. Max path length: 44 (base) + 42 (hex) = 86 chars. PVM limit: 250. Safe.

Kernel read errors must NOT be swallowed

In index_address, a store_read_all failure must distinguish PathNotFound (not registered → proceed to register) from other errors (I/O failure → propagate). Swallowing non-PathNotFound errors would cause duplicate registrations and counter desync.

What does NOT break (verified by audit)
  • CtxTrait extension: feature flag gates the new methods. When off, trait is unchanged. When on, Rust compiler forces all implementors to add the new methods. Only kernel_latest is affected (local path dep); 5 other kernels pin a git rev.
  • InterpretError: no exhaustive match exists. The only match on it (tzt/expectation.rs:64-80) ends with (_, _) => false. The From<SigCostError> impl (line 68) matches on SigCostError, not InterpretError.
  • Instruction enum: no serialization (no serde derives). Only one exhaustive match: interpreter.rs:284-1927 — handled by adding gated arms in commit 2.
  • Ctx::default(): used in 150+ tests. New fields are behind #[cfg], so existing Default is unchanged when feature is off.
  • No existing method modified: all 16 existing CtxTrait methods are untouched.

// Ctx impl:
#[cfg(feature = "address-registry")]
fn index_address(&mut self, address: &AddressHash)
    -> Result<BigUint, AddressRegistryError>
{
    let counter = &mut self.address_registry_counter;
    let index = self.address_registry
        .entry(address.clone())
        .or_insert_with(|| {
            let idx = counter.clone();
            *counter += BigUint::from(1u32);
            idx
        })
        .clone();
    Ok(index)
}

#[cfg(feature = "address-registry")]
fn get_address_index(&self, address: &AddressHash)
    -> Result<Option<BigUint>, AddressRegistryError>
{
    Ok(self.address_registry.get(address).cloned())
}

use tezos_smart_rollup_host::path::{concat, OwnedPath, RefPath};

const REGISTRY_PATH: RefPath = RefPath::assert_from(b"/address_registry");
const COUNTER_PATH: RefPath = RefPath::assert_from(b"/counter");

// Follows big_map root() pattern: context.path() + constant segment
fn registry_root<C: Context>(ctx: &C) -> Result<OwnedPath, PathError> {
    concat(&ctx.path(), &REGISTRY_PATH)
}

fn registry_counter_path<C: Context>(ctx: &C) -> Result<OwnedPath, PathError> {
    concat(&registry_root(ctx)?, &COUNTER_PATH)
}

// Follows value_path() pattern: hex-encoded hash as path segment
fn registry_entry_path<C: Context>(ctx: &C, addr: &AddressHash)
    -> Result<OwnedPath, PathError>
{
    let addr_hex = hex::encode(addr.to_bytes_vec());
    concat(&registry_root(ctx)?, &OwnedPath::try_from(format!("/{addr_hex}"))?)
}

mir_ctx.rs — Ctx<Host> implementation

Encoding: use Narith (newtype around BigUint with BinWriter/NomReader). Same pattern as BigMapId in generate_id() (line 373).

use tezos_data_encoding::types::Narith;
use tezos_storage::{read_nom_value, store_bin};

fn index_address(&mut self, address: &AddressHash)
    -> Result<BigUint, AddressRegistryError>
{
    let entry_path = registry_entry_path(self.tc_ctx.context, address)
        .map_err(|e| AddressRegistryError::Other(e.to_string()))?;

    // Invariant: distinguish PathNotFound from I/O errors.
    // Swallowing non-PathNotFound would cause duplicate registrations.
    match self.tc_ctx.host.store_has(&entry_path) {
        Ok(Some(_)) => {
            let n: Narith = read_nom_value(self.tc_ctx.host, &entry_path)
                .map_err(|e| AddressRegistryError::Other(e.to_string()))?;
            return Ok(n.0);
        }
        Ok(None) => {}
        Err(e) => return Err(AddressRegistryError::Other(e.to_string())),
    }

    // Follows generate_id() pattern (line 373): read counter, write, increment
    let counter_path = registry_counter_path(self.tc_ctx.context)
        .map_err(|e| AddressRegistryError::Other(e.to_string()))?;
    let counter: BigUint = read_nom_value::<Narith>(self.tc_ctx.host, &counter_path)
        .map(|n| n.0)
        .unwrap_or_else(|_| BigUint::from(0u32));
    store_bin(&Narith(counter.clone()), self.tc_ctx.host, &entry_path)
        .map_err(|e| AddressRegistryError::Other(e.to_string()))?;
    store_bin(&Narith(&counter + 1u32), self.tc_ctx.host, &counter_path)
        .map_err(|e| AddressRegistryError::Other(e.to_string()))?;
    Ok(counter)
}

fn get_address_index(&self, address: &AddressHash)
    -> Result<Option<BigUint>, AddressRegistryError>
{
    let entry_path = registry_entry_path(self.tc_ctx.context, address)
        .map_err(|e| AddressRegistryError::Other(e.to_string()))?;
    match self.tc_ctx.host.store_has(&entry_path) {
        Ok(Some(_)) => {
            let n: Narith = read_nom_value(self.tc_ctx.host, &entry_path)
                .map_err(|e| AddressRegistryError::Other(e.to_string()))?;
            Ok(Some(n.0))
        }
        Ok(None) => Ok(None),
        Err(e) => Err(AddressRegistryError::Other(e.to_string())),
    }
}

Bonus: View Restriction

Bonus Post-POC — commit 8

B
MIR: enforce view restrictions for side-effectful instructions
Bonus

This is a general MIR fix, not specific to the address registry. It fixes a pre-existing divergence where MIR allows side-effectful instructions in view bodies, while the OCaml protocol forbids them.

Scope

Forbid in view bodies: INDEX_ADDRESS, TRANSFER_TOKENS, SET_DELEGATE, CREATE_CONTRACT. Allow everywhere else. GET_ADDRESS_INDEX is read-only and allowed in views.

Implementation

1. Add in_view: bool to typecheck() and typecheck_instruction()

Simpler than a full TypecheckMode enum. A boolean is sufficient because we only need two states: "in a view body" vs "not".

The LAMBDA/LAMBDA_REC case: typecheck_lambda calls typecheck(..., in_view=false). This creates a new typechecking scope — in_view from the parent does not propagate into lambda bodies. Matches L1 behavior: Tc_context.add_lambda is a sticky flag in the OCaml protocol that prevents check_not_in_view from rejecting (see script_tc_context.ml:57-69). The effect is the same: forbidden instructions are allowed inside lambdas defined in views, because the lambda could be returned and executed elsewhere.
